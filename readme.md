<h1>Лабораторная работа №3</h1>
<b>Цель</b> работы -  создание веб-сервиса в бэкенде нашей системы для использования его в SPA

<b>Задание</b> - создание веб-сервиса со всей итоговой бизнес логикой (кроме авторизации), подключение его к БД и тестирование в postman

<h2>Структура базы данных</h2>

<b>users</b> - пользователи\
`id` - `bigint`, идентификатор пользователя, первичный ключ - `id`\
`login` - `varchar(25)`, логин, уникальное значение - `login`\
`password` - `varchar(100)`, пароль - не отдаётся в JSON\
`is_moderator` - `boolean`, признак модератора, по умолчанию `false` - не отдаётся в JSON\

<b>`planets`</b> - услуги\
`id` - `bigint`, идентификатор планеты, первичный ключ - `id`\
`name` - `varchar(50)`, название планеты, обязательное - `name`\
`description` - `varchar(255)`, описание планеты - `description`\
`distance_from_sun` - `numeric`, расстояние до Солнца, обязательное - `distance_from_sun`\
`perihelion` - `numeric`, перигелий - `perihelion`\
`observation_date` - `varchar(10)`, дата наблюдения - `observation_date`\
`image_url` - `varchar(150)`, имя файла изображения в MinIO - `image_url`\
`url_video` - `varchar(150)`, имя файла видео в MinIO - `url_video`\
`status` - `varchar(20)`, состояние записи: `draft`, `published`, `deleted` - не отдаётся в JSON\
`user_id` - `bigint`, владелец записи, внешний ключ на `users` - не отдаётся в JSON\
`created_at` - `timestamp with time zone`, дата и время создания - `created_at`\
`updated_at` - `timestamp with time zone`, дата и время изменения - `updated_at`\
`likes_count` - `integer`, количество лайков, вычисляется из таблицы `likes` - `likes_count`\
`liked` - `integer`, лайкнул ли текущий пользователь, `0` или `1`, вычисляется - `liked`\
`is_owner` - `integer`, текущий пользователь владелец записи, `0` или `1`, вычисляется - `is_owner`\

<b>`likes`</b> - лайки\
`id` - `bigint`, идентификатор лайка, первичный ключ - не отдаётся в JSON\
`user_id` - `bigint`, кто поставил лайк, внешний ключ на `users` - не отдаётся в JSON\
`planet_id` - `bigint`, чья планета, внешний ключ на `planets` - не отдаётся в JSON

<h2>Адрес сервера и общие правила</h2>

Адрес сервера: http://localhost:8080. Все методы начинаются с /api. Ответ — JSON самого ресурса, без обёртки: код состояния передаётся HTTP-статусом, тело при ошибке пустое. Текущий пользователь — константа singleton `auth.CurrentUserID()` (user, id = 1).

<h2>Методы HTTP</h2>

GET /api/planets — плитка: список опубликованных услуг с признаком `is_owner`, фильтрация по имени `?search=` и расстоянию от Солнца `?maxDist=`. Тело запроса: нет. Успех: 200 + массив услуг. Ошибки: 500 — ошибка базы данных.

POST /api/planets — создать черновик услуги с файлами изображения и видео. Тело запроса: multipart/form-data с полями `name`, `image_url`, `url_video`. Файлы необязательны: если их нет, подставляется дефолтное медиа. Успех: 201 + услуга. Ошибки: 400 — нет name или файл без расширения.

GET /api/planets/draft — черновик текущего пользователя, id не указывается (не более 1 записи). Тело запроса: нет. Успех: 200 + услуга. Ошибки: 404 — черновика нет.

PUT /api/planets/:id — публикация черновика, статус `draft` → `published`. Тело запроса: JSON с полями `description`, `distance_from_sun`, `perihelion`, `observation_date`. Успех: 200 + услуга. Ошибки: 400 — невалидные параметры, 404 — услуги нет или она уже не черновик.

GET /api/planets/feed — лента опубликованных услуг с признаком `liked`: без параметров первая, `?id=X&next=true` — следующая после X, с переходом на первую после последней. Тело запроса: нет. Успех: 200 + услуга. Ошибки: 400 — некорректный id, 404 — услуги нет.

POST /api/planets/:id/like — лайк от текущего пользователя: 1 поставить, 0 снять. Тело запроса: JSON `{"like": 1}` или `{"like": 0}`. Успех: 200 + услуга. Ошибки: 400 — некорректный id или значение like, 404 — услуги нет или она не опубликована.

DELETE /api/planets/:id — удаление услуги текущего пользователя, статус меняется на `deleted` (soft delete). Тело запроса: нет. Успех: 200 + услуга. Ошибки: 400 — некорректный id, 403 — услуги нет, она чужая или уже удалена.

POST /api/users — регистрация пользователя. Тело запроса: JSON `{"login": "user", "password": "123456"}`. Успех: 201 + пользователь. Ошибки: 400 — пустые или короткие поля, 403 — логин уже занят.

POST /api/users/auth — аутентификация, заглушка под лабораторную 4. Тело запроса: нет. Успех: 200.

POST /api/users/deauth — деавторизация, заглушка под лабораторную 4. Тело запроса: нет. Успех: 200.

<h2>Модель услуги в JSON</h2>

`id` · `name` · `description` · `distance_from_sun` · `perihelion` · `observation_date` · `image_url` · `url_video` · `likes_count` · `liked` · `is_owner` · `created_at` · `updated_at`

Поля JSON фиксированы: если значение пустое, поле всё равно присутствует (пустая строка или 0, не null).

`status` и `user_id` клиенту не передаются: статус услуги — системное поле, вместо `user_id` отдаётся `is_owner`.

`creator_id` в модели отсутствует: id создателя не выдаётся, вместо него `is_owner` — 1, если услуга создана текущим пользователем, иначе 0.

`likes_count` — количество лайков; в таблице не хранится, считается при сериализации.

`liked` — 1, если текущий пользователь лайкнул эту услугу, иначе 0 (вычисляется по таблице `likes`).

Эта модель возвращается во всех ответах с услугой: создание, черновик, публикация, лента, лайк, удаление. `is_owner` и `liked` считаются для текущего пользователя и присутствуют в каждом ответе, а не только в плитке или ленте.

Создание услуги двухступенчатое: POST создаёт черновик (`name`, `image_url`, `url_video`, остальные поля пустые), PUT /api/planets/:id заполняет `description`, `distance_from_sun`, `perihelion`, `observation_date` и переводит услугу в `published`. Вернуть услугу из `published` в `draft` нельзя.
